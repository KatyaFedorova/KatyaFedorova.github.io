Business Idea Evaluator

Python · FastAPI · Pydantic · Anthropic SDK · spec-driven + TDD

A sceptical early-stage investor in a web page — and a graded LLM eval pipeline that proves it behaves. You describe a business idea; it asks the questions whose answers would most change its verdict, researches the market with live web search, and only then decides: PROCEED, PROCEED ONLY AFTER TESTING X, or DON'T PROCEED. The verdict comes with the three strongest reasons it works, the three most likely ways it dies, the riskiest assumption, a two-week no-code validation plan with pass/fail numbers, named competitors and kill criteria. No scores, no pep talk, about 600 words.

The interesting half is the proof. Eight graded eval cases check behaviour, not format — that round one never judges early, that vague answers get sent back rather than a customer invented for the founder, that a prompt injection hidden in the idea text doesn't move the verdict, that an attached spreadsheet's numbers actually reach the report. Structural graders are paired with an LLM judge running on a cheaper model. Underneath sits a testing pyramid: 111 unit tests, 40 contract tests and 3 opt-in live integration tests, so the default suite is free, offline and fast. Cost is a first-class requirement — every call is priced, three spending ceilings are enforced before the API call rather than reconciled after it, and record/replay means debugging a live failure costs nothing. One production evaluation runs at $1.30; the full eval suite at $0.48. Built spec-first with GitHub Spec Kit and strict TDD, under a written project constitution.

What I'd do differently: pay attention to the cost of the evaluation pipeline far earlier — at the specification stage, not after it works. I'd move to a cheaper model for the eval runs from the start and do the budget maths before running the pipeline rather than discovering the bill afterwards.

TomatoPaws

Kotlin Multiplatform · iOS · Android · web

A desk-break app for white-collar workers: a Pomodoro timer paired with guided fitness breaks, built to keep blood moving through a day spent in a chair. One codebase, three platforms — iOS, Android and web.

This one is my baby. It's the first application I released myself, and I was every role on it: developer, product owner, QA, business owner and the person whose idea it was in the first place. It's also where the LLM work lives — personalised break suggestions behind one provider-agnostic interface, with the eval set, rubric and CI regression gate that judge them.

What I'd do differently: beta testing and user research before building, not after. I built first and learned what people actually wanted second, which is the expensive order to do it in.
